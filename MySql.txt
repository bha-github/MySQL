------------ select expressions are evaluated

# Write your MySQL query statement below
SELECT
    DATE_FORMAT(trans_date, '%Y-%m') AS month,
    country,
    COUNT(*) AS trans_count,
    COUNT(IF(state = 'approved', 1, NULL)) AS approved_count,
    SUM(amount) AS trans_total_amount,
    SUM(IF(state = 'approved', amount, 0)) AS approved_total_amount
FROM
    Transactions
GROUP BY
    month,
    country
	
1. FROM Clause
MySQL first identifies the table (Transactions) from which the data will be queried.
The data is loaded into memory for further processing.
2. WHERE Clause
Although not present in your query, if there were any conditions specified in the WHERE clause, MySQL would filter rows from the Transactions table based on those conditions.
3. SELECT Clause (Evaluates Expressions for Columns)
Expressions like DATE_FORMAT(trans_date, '%Y-%m'), COUNT(*), SUM(amount), and conditional aggregates such as COUNT(IF(state = 'approved', 1, NULL)) and SUM(IF(state = 'approved', amount, 0)) are evaluated.
The SELECT clause is processed after GROUP BY logically, but the column expressions are prepared here for aggregation.
4. GROUP BY Clause
Rows are grouped based on the GROUP BY columns: month (derived from DATE_FORMAT(trans_date, '%Y-%m')) and country.
For each unique combination of month and country, MySQL aggregates the data using the specified aggregate functions (COUNT, SUM, etc.).
5. Aggregate Functions
Within each group, the aggregate functions are computed:
COUNT(*) calculates the total number of rows in each group.
COUNT(IF(state = 'approved', 1, NULL)) counts rows with state = 'approved' in each group.
SUM(amount) computes the total amount for all rows in each group.
SUM(IF(state = 'approved', amount, 0)) computes the total approved amount in each group.
6. ORDER BY Clause (Optional)
If there was an ORDER BY clause, MySQL would now sort the aggregated results based on the specified columns or expressions.
7. Result Set
After all processing steps, MySQL returns the final result set with the grouped and aggregated data.

------------ LAG function
LAG (scalar_expression [, offset [, default ]])     OVER ( [ partition_by_clause ] order_by_clause )

Where: 

scalar_expression – The value to be returned based on the specified offset.
offset – The number of rows back from the current row from which to obtain a value. If not specified, the default is 1.
default – default is the value to be returned if offset goes beyond the scope of the partition. If a default value is not specified, NULL is returned.
partition_by_clause: An optional clause that divides the result set into partitions. The LAG() function is applied to each partition separately.
order_by_clause: The order of the rows within each partition. This is mandatory and must be specified.

Why Use the LAG() Function?
Comparing Rows: Helps compare the current row with a previous row’s data.
Trend Analysis: Useful for analyzing changes in values, like stock prices, sales figures, or other time-series data.
Finding Differences: Calculate the difference between consecutive rows in terms of time, quantity, or any other metric.

SELECT Organisation, [Year], Revenue,
LAG (Revenue, 1, 0) 
OVER (PARTITION BY Organisation ORDER BY [Year]) AS PrevYearRevenue  
FROM Org 
ORDER BY Organisation, [Year];

DELIMITER **

CREATE PROCEDURE primeNumbers()
BEGIN
    DECLARE n INT DEFAULT 3;
    DECLARE result VARCHAR(2000) DEFAULT "2";
    
    loop1: WHILE n<=1000 DO
        SET @i = 2;
        SET @isPrime = 1;
        
        loop2: WHILE @i<=CEIL(n/2) DO
            IF n % @i = 0 THEN
                SET @isPrime = 0;
                LEAVE loop2;
            END IF;
            
            SET @i = @i + 1;
        END WHILE loop2;
        
        IF @isPrime = 1 THEN
            SET result = CONCAT(result, "&", n);
        END IF;
        
        SET n = n + 1;
    END WHILE loop1;
    
    SELECT result;
END**

DELIMITER ;

CALL primeNumbers()
